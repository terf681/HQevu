# EVU HQ («Штаб»)

Статика (`login.html`, `index.html` — Штаб, `admin.html` — админка владельца, `hq.css`, `core.js`, `config.js`) + Supabase (Postgres + Edge Functions).
**Без настройки работает ДЕМО-режим** (данные в вашем браузере). Демо-ключи: `EVU-OWNER-DEMX-2345`, `EVU-CMD-DEMX-2345`, `EVU-MBR-DEMX-2345`.

## Что есть в админке
- **Главная:** численность (всего / активные / отпуск / исключённые), последние повышения, быстрые ссылки.
- **Ростер:** поиск, фильтры по подразделению, рангу и статусу, добавление бойца.
- **Личное дело:** повысить, понизить, перевести, исключить, восстановить, отпуск, назначить инструктором, сменить позывной; история повышений; заметки офицеров (видны только командованию и владельцу); статистика инструктора.
- **Подразделения:** карточки с командиром, составом и распределением по рангам.
- **Академия:** новобранцы, 3 этапа (ПВП, Устав, База и морфы) строго по порядку, выпуск и зачисление в состав; инструкторы со статистикой.
- **Админка (`admin.html`, только owner):** генерация и отзыв ключей (24 ч / 7 дн / 30 дн / бессрочно), ранги, подразделения, журнал действий.

## Права
| Роль | Может |
|---|---|
| member | смотреть ростер, подразделения, академию; инструктор-боец принимает этапы |
| commander | всё выше + менять состав, заметки, академия; **только бойцов ниже своего ранга и до рангов ниже своего** |
| owner | всё, включая ключи, ранги, подразделения, журнал |

Ограничения проверяются на сервере. Нельзя менять собственный ранг (кроме owner), нельзя отозвать ключ, под которым вы вошли. Записи о повышениях добавляются атомарно (функция `hq_member_change`) и защищены триггером от изменения и удаления.

## Запуск
1. В **том же** проекте Supabase выполните по порядку: `recruit/supabase/schema.sql` (если ещё нет), `hq/supabase/hq_schema.sql`, `hq/supabase/hq_schema_2.sql`.
2. Первый ключ владельца: раскомментируйте блок в конце `hq_schema.sql`, подставьте свой Discord ID и **свой** ключ `EVU-OWNER-XXXX-XXXX` (буквы без I и O, цифры 2–9). Сам ключ в БД не хранится, только хэш. Остальные ключи генерируются в админке.
3. Скопируйте `hq/supabase/functions/*` в `supabase/functions` проекта и задеплойте: `supabase functions deploy staff_login` и `supabase functions deploy hq`.
   Для смены ролей Discord при повышении нужны секреты `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID` (те же, что у рекрутинга) и `discord_role_id` у рангов (роль бота должна стоять выше ролей рангов).
4. В `config.js` укажите `SUPABASE_URL` и `SUPABASE_ANON_KEY`.
5. Ранги не заполнены намеренно: создайте свою структуру в Настройки → Ранги.

## Безопасность входа
Ключ хранится только как SHA-256 хэш; в браузере лежит случайный токен сессии (до 7 дней или до конца срока ключа). Отзыв ключа обрывает сессии сразу. 8 неудачных попыток за 15 минут с одного IP блокируют вход. Все действия пишутся в `admin_log` (`scope = 'hq'`).

## Проверено / не проверено
Демо-режим прогнан автотестом (jsdom): вход, роли и ограничения, повышения/переводы/исключение, ключи (создание, отзыв), ранги, подразделения, академия, интерфейс — без ошибок JS.
**Edge Functions и SQL против настоящего Supabase в этой среде не запускались.** Проверьте на тестовом проекте: вход, повышение, генерацию ключа.
Не сделано: аналитика и отчёты (последний пункт ваших приоритетов), разделение просмотра ростера по подразделениям.
